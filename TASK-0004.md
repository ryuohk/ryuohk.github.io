## Decisions and open questions

- Show all members, including the earliest-created reference copy (ID breaks creation-time ties). Reference is informational, not protected. No automatic selection or deletion. The UI warns that Select shown includes every visible copy.
- Keep duplicate groups adjacent and label each row with group number and full-library group size. Group numbers are presentation labels and may change after library changes.
- Compare question prompt, ordered labelled choices, correct-answer label set, and ordered images with their question/answer roles. Explanation, discussion, source/exam/topic metadata, community votes, alt descriptions, notes and ratings do not participate.
- Image equality: exact embedded data URL if present; otherwise exact stored URL after existing whitespace normalization. Embedded and URL-only representations differ. Different source URLs with identical embedded data match. This is available offline and avoids fetching assets; it does not decode bytes, hash files or compare rendered pixels. Different encodings of the same picture can remain distinct.
- Text normalization uses the existing normalizeWhitespace primitive: NBSP becomes space, runs of tabs/CR/spaces collapse, whitespace around newlines is removed, repeated newlines collapse, outer whitespace is trimmed. No case folding, smart-quote replacement or Unicode normalization. Choice labels uppercase and remove trailing period/parenthesis; answer labels uppercase and compare as sorted sets. Choice and image order matter.
- Manual areLibraryDuplicates/libraryDuplicateKey and automatic questionContentKey are separate, independently tested equality policies. Only the whitespace primitive is shared. No automatic deduplication code changed. Tests establish that explanation/discussion variants match manually but remain distinct automatically.
- Detect groups across the current consolidated library, then intersect with exam, topic, group, label and search filters. A narrowed view may show one member whose partner is elsewhere; the UI explains this. Fully identical backing records already consolidated by TASK-0003 remain consolidated. Missing/incomplete captured records are skipped.
- Toggling the filter clears selection. Filter state is not persisted. Deletion recomputes groups; once one copy remains, it disappears from duplicates-only and appears in the normal library. Existing selection, ownership checks, confirmation, alias expansion, removeCards, sync and study-session cleanup remain unchanged.
- The final supplied open question is truncated at "What happens to m"; its intended wording cannot be recovered. If it concerns mastery, filtering does not change mastery or history and deletion does not transfer history to a survivor. The existing delete path removes the selected copy and its rating history; the survivor retains its own data and normal study eligibility. No new merge behavior was introduced. These are implementation decisions, not a claim of explicit user confirmation of the truncated question.
